FILE DESCRIPTIONS
-----------------

Core Python Models (models/)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~

donation_fund.py:
  - Model: donation.fund
  - Fields: name, code, description, account_id, active
  - Computed: donation_count, total_amount, currency_id
  - Purpose: Tracks restricted funds/purposes for donations

donation_campaign.py:
  - Model: donation.campaign
  - Fields: name, date_start, date_end, goal_amount, fund_id, description, active
  - Computed: total_raised, donation_count, progress_percent, is_active_campaign
  - Purpose: Tracks fundraising campaigns with progress

donation_donation.py:
  - Model: donation.donation
  - Fields: donor_id, date, amount, currency_id, payment_method, cheque_number,
            fund_id, campaign_id, reference, receipt_number, state, note,
            journal_id, move_id
  - Methods: action_confirm(), action_generate_receipt(), action_post_to_accounting(),
             action_view_accounting_entry(), action_set_to_draft(), action_print_receipt()
  - Purpose: Core donation record with full workflow

donation_year_end_wizard.py:
  - Model: donation.year.end.wizard (TransientModel)
  - Fields: donor_id, year, total_donations, donation_count
  - Methods: action_generate_statement(), action_generate_csv()
  - Purpose: Wizard to generate year-end PDF statements

View XML Files (views/)
~~~~~~~~~~~~~~~~~~~~~~~

donation_donation_views.xml:
  - Contains: Tree, Form, Search, Pivot, Kanban views for donations
  - Menu: Main "Donations" menu with action
  - Features: Status buttons, workflow, GL entry view

donation_fund_views.xml:
  - Contains: Tree, Form, Search views for funds
  - Menu: "Funds" submenu under Donations
  - Features: Stat buttons for donation count & total raised

donation_campaign_views.xml:
  - Contains: Tree, Form, Search views for campaigns
  - Menu: "Campaigns" submenu under Donations
  - Features: Progress bar widget, active campaign tracking

donation_year_end_wizard_views.xml:
  - Contains: Form view for wizard
  - Menu: "Reports > Year-End Statements" submenu
  - Features: Donor/year selection, summary display

Report XML Files (report/)
~~~~~~~~~~~~~~~~~~~~~~~~~~

donation_receipt_report.xml:
  - Report: nonprofit_donation_mgmt.report_donation_receipt
  - Template: report_donation_receipt_template (QWeb)
  - Output: Professional PDF receipt with:
    * Organization letterhead placeholder
    * Donation details
    * Donor information
    * Amount in figures
    * Tax deduction notice
    * Signature line

  - Report: nonprofit_donation_mgmt.report_donation_year_end
  - Template: report_donation_year_end_template (QWeb)
  - Output: Annual donor statement with:
    * All donations for year
    * Donation table (date, ref, fund, amount)
    * Total summary
    * Tax notice

Data XML Files (data/)
~~~~~~~~~~~~~~~~~~~~~~

donation_sequence.xml:
  - Sequence: seq_donation_donation
    Prefix: DON-%(year)s-
    Padding: 5 digits
    Usage: Auto-generates donation reference numbers
  
  - Sequence: seq_donation_receipt
    Prefix: RCP-%(year)s-
    Padding: 6 digits
    Usage: Auto-generates receipt numbers

WORKFLOW STATES
---------------

Draft:
  - Initial state
  - Can edit all fields
  - Not counted in reports
  - Can reset to draft

Confirmed:
  - Validated donation
  - Reference number assigned
  - Can generate receipt
  - Can post to accounting
  - Cannot edit donor/amount

Receipted:
  - Receipt generated
  - Receipt number assigned
  - Can print receipt
  - Can view GL entry
  - Final state

LIMITS & CONSIDERATIONS
-----------------------

- Reference numbers reset yearly (can modify in sequence)
- Single currency per company (no multi-currency donations)
- GL posting requires account module
- Year-end statements generated on-demand (not scheduled)
- No built-in recurring/pledge system (can add separately)
- No donation online form (web contact form can integrate)
- Receipt PDF uses company letterhead (configure company info)


NOTES FOR DEVELOPERS
--------------------

- All models inherit mail.thread for messaging
- Full datetime tracking on all records
- Constraints: reference unique, amount positive, cheque unique per donor
- Computed fields auto-recalculate on model changes
- Report templates use Jinja2 + QWeb syntax
- Security via CSV ACL (not record rules)
- No demo data included (populate manually)
- Multi-language ready (field labels are translatable)
